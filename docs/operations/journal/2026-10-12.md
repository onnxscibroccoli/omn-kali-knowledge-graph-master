## ~22:15 EDT: OCI v2 result and root cause correction

The user ran **OCI audit v2** on the physical Android:

- `us-ashburn-1`, **2 compartments** checked, **3 availability domains** enumerated; `Grasshopper-Workstation` remains **RUNNING** as `VM.Standard.A1.Flex`.
- 8 recognized resources across compute instance, block/boot storage and attachments, one VCN, subnet, and ephemeral public IP.
- `76` CLI calls, `32` `EMPTY_STDOUT_EXIT0` cases (20 tenancy-root, 12 Grasshopper), retries without `--all` also blank; **zero** nonblank error classes reported.

**Source-level diagnosis:** The OCI CLI implementation `src/oci_cli/cli_util.py` `render()` tests `if data:` before building the display dictionary and only prints when it is non-empty. An OCI API **empty list `[]` therefore produces zero stdout and process exit 0**, even with `--output json`. This contradicts the assumption in our v1/v2 scripts that every successful list operation must produce JSON. This is an **audit parser defect**, not itself an OCI infrastructure fault; the 32 records are strongly consistent with empty resource lists, but need SDK cross-check for proof.

Oracle source: https://github.com/oracle/oci-cli/blob/master/src/oci_cli/cli_util.py (render function, lines near 3551 and 3587 as observed 2026-10-12). A syntax-checked reconciliation script `termux_oci_audit_reconcile.sh` reads v2 without rescanning all 76 calls and uses the OCI Python SDK `SecurityTokenSigner` to independently check tenancy-root empty lists, the Grasshopper instance, VNIC and volume sizes. **Not yet run on the device**.

**Guardrail:** Eight discovered entries describe only the resource families queried by v2 and do not establish a complete cloud billing/IAM/quotas inventory. No infrastructure resources modified. Maintain existing private reports and do not commit raw OCIDs/tokens.
